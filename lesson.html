How to check a Python script for syntax errors without running it

Short answer

A missing colon or a wrong indent stops a Python script before it does anything. This lesson builds a small read-only Python tool that asks Python's own parser to read a script and reports the line, the message and the position of the first syntax error. The tool has no code that runs the script. When the script parses, it counts the functions and classes and lists the modules it imports. It checks syntax only: a script that passes can still crash when it runs.

Follow along and build it step by step. You add each file yourself, run each command, and see the real recorded result.

Common mistakes

  1. Counting lines and calling it a check. The first version in this lesson counts lines and def lines. It says nothing about whether Python would accept the file.
  2. Running a script to find out if it parses. Running does what the script says. The tool asks the parser to read the file instead, and a test checks that a script that would create a file does not create one.
  3. Fixing everything at once. The parser stops at the first syntax error, so the tool shows only that one. Fix it and run again.
  4. Treating a pass as proof the script works. A script can parse and still crash when run, use a name that does not exist, or import a module that is not installed. The tool lists imports but does not check them.

Frequently asked questions

How do I check a Python script for syntax errors without running it?

Read the file and pass it to the ast module's parse function. If the file is not valid Python it raises a syntax error with the line number. This lesson builds a small tool around that.

Will this run my script?

No. The tool only parses it. A test checks that parsing a script containing a statement that would create a file does not create the file. That is the only evidence for this claim.

Will this change my script?

No. The tool only reads the file. A test checks that one small script has the same bytes and the same modified time before and after a run.

Why does it show only one error?

The parser stops at the first syntax error. Fix it and run the tool again to see the next one.

Does it check that imported modules exist?

No. It lists the first part of each imported module name and says they are not checked.

Does it work for any Python version?

It checks the file with the Python you run it with. A script written for a different Python version may be judged differently.
